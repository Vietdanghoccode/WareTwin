# AGENTS.md

WareTwin — browser-native 3D warehouse digital twin. React/TS frontend + FastAPI backend,
running the same simulation in two languages.

## Non-obvious facts

- **Two hand-mirrored engines**: `frontend/src/simulation/engine.ts` and `backend/app/sim/engine.py`.
  The backend is authoritative when the WebSocket is connected; the TS engine is the LOCAL fallback.
  FSM, Fleet Manager weights, A*, navgrid rules and task validation are duplicated by hand — change both sides.
- **TwinState contract**: `frontend/src/schema/twin_state.ts` ≡ `backend/app/schema.py` (Pydantic).
  Edit both runtime definitions when changing the contract.
- **Layout copies**: `warehouse_layout.json` is byte-identical in `frontend/src/layout/` and `backend/app/`.
  It is generated by `docs/layout/gen_layout.py`; regeneration commands are in the root README.
- **PRNG parity**: both engines use the same RNG and tick order. Changing either breaks cross-language parity.
  What-if runs only on the backend (deep-cloned engine).
- **Stateful service**: the backend is a long-running WebSocket process (not serverless); state lives in memory
  plus SQLite (`backend/twin.db`, gitignored). The hosted demo is one shared simulation.
- Comments/docstrings are mixed Chinese/English/Vietnamese — match the local file; don't translate unrelated text.

## Commands

Run each side from its own directory (imports and paths assume it).

Backend (`backend/`):
```bash
pip install -r requirements.lock          # fully pinned; used by Render/Docker/CI
uvicorn app.main:app --reload --port 8000
python -m pip check
python -m compileall -q app
TWIN_DB=:memory: TWIN_MQTT_ENABLED=0 TWIN_ALLOCATION_MODE=internal python -c "from app.main import app, server; from app.schema import TwinState; TwinState.model_validate(server.engine.state)"
```
Add a runtime dep to `requirements.txt`; regenerate `requirements.lock` (CI installs the lock, then runs `pip check`).

Frontend (`frontend/`):
```bash
npm ci
npm run dev                # http://localhost:5173
npm run build              # tsc --noEmit && vite build (this is the typecheck)
npm run preview
```

CI (`.github/workflows/ci.yml`): backend Python 3.11 checks dependencies, compilation, application imports
and the initial TwinState; frontend Node 20 runs `npm run build`.

## AI / config

- No API key is required: Copilot falls back to rule-based analysis and VLM to simulated perception.
- Backend reads `backend/.env` (copy `.env.example`): `OPENAI_API_KEY`, `TWIN_SEED`, `TWIN_DB`, guard vars.
  `TWIN_RATE_LIMIT=0` disables rate limiting locally.
- `backend/app/guard.py` enforces input limits, rate limits, Origin checks and body caps; task-location rules
  are mirrored in `backend/app/sim/rules.py` and TS `rules.ts`. Update both when changing validation.
- Frontend backend address: `VITE_WS_URL` (defaults to `ws://<hostname>:8000/ws`).
- Optional MQTT / external allocation setup: `docs/ditto/README.md`.
